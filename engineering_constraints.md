# Engineering constraints

Windows only. The reader is Node (`app/reader/`), not a frozen CPython sidecar
— see Packaging.

## What exists

`app/reader/` attaches to `Ravenswatch.exe`, builds a GlobalValue index on
a worker thread and re-checks it every 5 s, and polls resolved addresses at
`POLL_MS` (250 ms). Two more workers own the Sandman shop and the placed-tile
roster. `readState()` turns one poll into plain data; the renderer renders
from it and nothing else:

- the Electron app in `app/`, which spawns the reader
  (`app/reader/stdio.js`) and forwards each frame to the
  renderer over IPC
- JSON stream on stdout — `node app/reader/stdio.js`, one object per line at
  the poll interval, which is the same command the app spawns

A frame is a fixed set of keys, asserted by `test-stdio`. That contract is what let
the renderer swap transports without changing what it draws.

## The app

```
app/main.js      main process: window, IPC, app lifecycle
app/sidecar.js   supervision of the reader process; no Electron, no channels
app/reader/      the memory reader in Node — see its own README
app/preload.js   the contextBridge surface — two subscribe functions, one-way
app/README.md    running from source, building, first-launch warning
app/web/         the page — plain HTML/CSS/JS, no build step, no framework
```

A 1280x800 `BrowserWindow`, not an overlay. `contextIsolation` on,
`nodeIntegration` off, sandboxed preload. Single-instance lock; a second
launch focuses the first window. The sidecar is tree-killed on quit, and
backstopped by a stdin dead-man's switch for hard external kills.

Memory access is read-only throughout:
`PROCESS_QUERY_INFORMATION | PROCESS_VM_READ`, never `VM_WRITE`, no
injection, no elevation manifest.

## Packaging

Build and install steps, the SmartScreen warning, and the asar verification
are in `app/README.md`. The reader runs on Electron's own Node runtime: `process.execPath`
with `ELECTRON_RUN_AS_NODE=1` is the spawn command from source and packaged
alike, so neither layout needs Python. `sidecar.js` locates both reader
inputs (`value_types.json` and an explicitly supplied `.gen` tree) and passes them as
environment variables; `app/reader/README.md` has the detail.

Packaged, `app/web` and `app/reader` keep their places inside the asar.
The one thing that cannot live in the asar is koffi's
native `.node`, which a loader must read as a real file — `asarUnpack`
covers `**/*.node` and Electron rewrites the require path to
`app.asar.unpacked`. `main.js` and `sidecar.js` resolve everything from
app-relative anchors (`__dirname`, `process.resourcesPath`), never relative
to the source tree.

**The executable icon is `app/build/icon.ico`**, generated by
`app/scripts/build-icon.js` from an original block-letter R at build time.
It contains no game art. `app/build/` is the build-resource directory;
the root `build/` directory holds staging and distribution output.

## Traps already paid for

- **Map ids start at 0**: Dark Hills `0`, Storm Island `1`, Avalon `2`,
  Baba Yaga `3`. Live code reads the mapping out of the process.
- **`Current map id` reads `-1` while no run is loaded**, and sits there for
  around 20 s between runs. It is a real reading, not an error and not
  unresolved, and it is the only positive signal that a run ended -- a
  restart onto the same map is `0 -> -1 -> 0`, so anything comparing only
  the map ids on either side sees no change at all. Note it leads
  `Hero Level` by about ten seconds: map id reaches `-1` while the level is
  still whatever the run ended at. The `-1` alone separates "between runs"
  from "loading the next map mid-run", because a mid-run load never passes
  through it. Do not pair it with a level term: the main menu reads level
  `1` before any hero exists, so a level test reports the menu as a run.
- **`handle` is reserved on a request handler.** `Handler.handle` shadows
  `BaseRequestHandler.handle()` and every request dies with a `NoneType`
  error. It's `proc_handle` for that reason.
- **A zero is usually a real reading.** Questlines you aren't on sit at 0
  all run; the one you are on reads 0 until it starts. Unresolved and zero
  are different states — keep the distinction through any rewrite.
- **`index.html` ships the unresolved vocabulary as static markup** — `—`,
  `unresolved`, `?`, `not decoded yet`, `resolving…`. A screenshot showing
  those strings cannot distinguish a working transport from a dead one; it
  is exactly what a page with a broken preload displays. Evidence that
  frames are arriving must be a value that only exists when data does: a
  hero level, a sweep counter, a quest step label.
- **A failed spawn emits `close`, never `exit`.** Listening on `exit` alone
  means a missing or quarantined sidecar notifies nothing — no down-state,
  no retry, and a window that looks like it's still on its first sweep.
- **A sandboxed preload can't `require` a local file.** Electron sandboxes
  preloads by default; `require('./channels')` throws and abandons the whole
  script before `contextBridge.exposeInMainWorld` runs. Channel-name
  literals are duplicated between `main.js` and `preload.js` deliberately.
- **The first sweep lands around 3.5s.** Before it, everything is legitimately
  unresolved: 0/11 at t+0.8s, 11/11 at t+3.6s. Still unresolved past ~10s
  with the game running is a real fault.
- **The values index is held across sweeps.** A full build is a 1.7 GB
  writable-heap scan (1600-1935 ms live); a held binding reads in three
  calls. Every tracked binding kept its address for the life of the game
  process: a Dark Hills -> Storm Island transition, five run restarts and
  seventeen level-ups across two sessions (`bench/binding-stability.js`,
  2026-09-15 and 2026-09-18). The sweep rebuilds only on `indexRebuildDue`'s
  signals: no index, a tracked name not resolving `ok`, map change, run
  reset. The last two are a belt against a freed-but-not-reused binding,
  not a measured need.
- **Tiles and Sandman are off the sweep.** Each has its own worker
  (`tiles-worker.ts`, `sandman-worker.ts`), because the ~1.3 s selector scan
  and the 100 ms shop poll both lose when they share a thread with the 5 s
  discovery sweep. The sweep worker posts `mapId` and `runReset`; `Reader`
  relays map changes and resets to the tile worker on change only.
- **Icons are decoded at runtime.** `app/web/assets/SOURCES.tsv` maps cache
  names to game resource paths. No decoded icons are included. The vendored
  font has separate provenance and license in `app/web/assets/fonts/`.
- **`koffi.view()` is fatal under Electron.** It wraps external memory in an
  ArrayBuffer via `napi_create_external_arraybuffer`, which Electron's V8
  sandbox rejects — not as a catchable exception but as `FATAL ERROR:
  Error::New napi_get_last_error_info`, which kills the process. Reproduces
  on the first call in both the dev binary and the packaged app, on koffi
  2.16.3 and 3.1.6 alike, while plain `node` runs the same code fine. A Node
  `Buffer` is the substitute and costs nothing: measured 3.32/3.13/2.98 GB/s
  against `view()`'s 3.28/3.24/3.02 GB/s. The "a Buffer would marshal a copy
  per call" assumption the original code was built around is false — koffi
  passes a Buffer's data pointer.
- **The sweep has to stay on a worker thread.** Python's runs on a plain
  background thread because ctypes drops the GIL for every
  `ReadProcessMemory` and numpy drops it for the comparison. Node's scan is
  plain JS and blocks: measured worst poll gap 1127 ms on the main thread
  against 323 ms on a worker, on a 250 ms loop.
- **Never touch BigInt in the scan loop.** Windows x64 user addresses fit in
  a JS Number, so the scan is split-word `Uint32Array` throughout. A
  `BigUint64Array` version measures ~4x slower and `Buffer.indexOf` per
  target lands near the `bytes.find` class that could not keep up with the
  5 s sweep interval at all.
- **The reader's only argument is an optional PID.** `stdio.js` rejects
  anything that does not parse as one. A stray flag handed to `OpenProcess`
  as `NaN` reports `GetLastError=87` instead of the game-not-running message.
- **A packaged reader can be tested without opening a window.**
  `ELECTRON_RUN_AS_NODE=1 "<app>.exe" <asar-path>/reader/stdio.js`
  runs the shipped reader out of the shipped asar and prints frames to the
  terminal. That is how the asar mapping, the unpacked `.node`, koffi under
  Electron, and live value parity were all checked without launching the
  GUI.
- **`appId` does nothing at runtime.** electron-builder writes it into NSIS
  installer shortcuts, and this app has no installer, so Windows was falling
  back to an AppUserModelID derived from the executable path. `main.js` sets
  it explicitly and the string must stay equal to `build.appId` — nothing
  enforces the pairing.
